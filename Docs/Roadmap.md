# 로드맵

> 기능을 구현하거나 기획이 바뀌면 이 문서를 갱신할 것.

## ✅ 구현 완료

- [x] 5층 랜덤 맵 생성 (Tilemap, 층별 광물 min~max)
- [x] 플레이어 좌우 이동, 벽타기(Shift, 파낸 공간 안에서만)
- [x] 마우스 8방향 조준 + 포인터
- [x] 누르고 있기 채굴, 곡괭이 단계별 채굴 시간표 (BlockCatalog)
- [x] 채굴 균열 애니메이션
- [x] 깊이/구역 판정 (광산 진입, 상단 4칸 귀환 구역)
- [x] 랜턴 (광산 안에서만 10초/칸 감소) + UI
- [x] 랜턴 소진 → 암전 → 다음 날 (씬 재로드)
- [x] 깊이 게이지 UI
- [x] 캐릭터 애니메이션 (앞/뒷모습, 대기·이동·벽타기·채굴)

## 🔜 개발 예정 순서 (사용자 확정)

> 이 순서대로 진행한다. 순서를 바꾸자고 제안할 수는 있지만 임의로 건너뛰지 말 것.
> 각 항목의 "포함 범위"는 해당 단계에서 같이 처리하면 좋은 것들.

1. [x] **캐릭터 애니메이션 적용** — 완료, 플레이 테스트 통과 (→ `01_Player_Controls.md` "애니메이션 상태")
   - 대기/이동/벽타기/채굴 상태 전환, 채굴 애니메이션 재시작 + 채굴 시간에 맞춘 속도
   - 뒷모습 채굴 애니메이션은 없음 (추후 제작 시 추가)
   - Break 애니메이션 레이어 문제는 아래 "수정 필요 (보류 중)" 참고
2. [ ] **세이브 기능 (이어하기 대비)**
   - 먼저 저장할 **플레이어 데이터** 구조를 정할 것: 일차, 소지금(마이너스 가능), 곡괭이 단계, 클로 단계, 아이템 보유량, 배송 대기 주문
   - 기획 확정 전에는 `09_Save_Data_Test.md`의 **테스트용 임시안**으로 세이브 동작을 먼저 확인한다 (기획 수정 → 코드 반영)
   - 씬 재로드 후에도 유지되어야 함 (GameManager 또는 별도 데이터 클래스)
   - 저장 시점: 취침 시 자동저장
3. [ ] **해당 일차의 획득 광물 저장**
   - 블록 파괴 시 광물을 그날의 획득 목록에 추가 (`MiningController.OnBlockBroken` 활용)
   - 흙은 집계 제외
4. [ ] **일차 기능**
   - 현재: 랜턴 소진 → Day+1 → 씬 재로드까지만 구현
   - 추가: 지상 귀환 → 까마귀 회수 → 귀가/취침으로 하루를 끝내는 정상 흐름 (지금은 지상에선 랜턴이 안 줄어 하루가 끝나지 않음)
5. [ ] **광물 정산 기능**
   - 광물 가격표 데이터화 (`05_Economy.md`), 핸드폰 정산 화면
6. [ ] **조난 처리**: 획득 광물 50% 제거 + 구출 비용 지불 (마이너스 계좌)
7. [ ] **인벤토리 기능**
   - 아이템 보유량, 최대 보유량 제한 (`06_Items.md`), 클릭으로 사용
8. [ ] **인터넷 쇼핑**: 곡괭이 강화 + 아이템 구입
   - 주문은 다음 날 아침 도착 (배송 대기 목록 → 기상 시 지급)
9. [ ] **아이템별 개별 기능** (추후 기획에 따라 일정 수정)
   - 다이너마이트 Lv1~3, 보조배터리, 에너지 음료, 커피, 클로
10. [ ] **뉴스 (시세 변동 기능)**
11. [ ] **구매한 물건 획득 연출** (풍선 배송)
12. [ ] **빌드 테스트 및 오류 수정**

## ❓ 결정이 필요한 항목

구현 전 사용자에게 확인할 것.

- 시세 변동 폭, 하루에 변동되는 광물 수
- 구출 비용, 마이너스 계좌 한도
- 하루 종료 트리거 (지상 도착 자동 vs 침대 상호작용)
- Lv3 곡괭이의 흑요석 채굴 가능 여부 (시트 빈칸, 코드 0.9초)
- 다이너마이트 Lv2의 내핵 사용 가능 여부
- 시트의 "클로 +2" 두 번째 줄 = 클로 +3이 맞는지
- Lv3~Lv5 곡괭이 이름
- 특수 광물, 도전과제 내용
- 15일 이후 목표 / 엔딩

## 🧹 정리 필요 (사용자가 Unity 에디터에서 직접)

- `TileBreaker.ClickBlock`은 빈 함수 (씬의 PlayerInput 이벤트 연결 해제 후 삭제 가능)

## 🛠 수정 필요 (보류 중)

- **Break(균열) 애니메이션이 플레이어의 곡괭이보다 위에 그려짐**: 곡괭이가 균열에 가려 보인다. 애니메이션 전체의 정렬 레이어(Sorting Layer / Order in Layer) 조정이 필요해서, 당장은 수정을 미루고 보류한다. 캐릭터 애니메이션(순서 1번) 마무리 시점에 레이어 전반을 함께 정리할 것.
